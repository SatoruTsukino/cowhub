# Plan 1.6: Remote Chomp Target Validation (reject reduction)

## Objective
In Remote mode, about a third of grass bites are rejected. Source: UAT log `chomp_1793855223.jsonl`, 587 sends: 394 accepted, 82 OutOfRange, 69 Unavailable, 38 BehindCow, 4 ChewCooldown. Pacing is fine (ChewCooldown is 0.7%); the problem is target selection:
- **Unavailable:** 52 of 69 are re-bites on grass the hub ate 0.5–6 s earlier. One bite consumes a node, and Consumed→Consumed on the same node is never under 11.3 s. The hub only blocks the last node for `interval + 0.2` (about 0.6 s).
- **OutOfRange / BehindCow:** the hub picks nodes by 2D distance from the current root position. It never checks facing, and ignores the cow's movement during the request's flight. The game's `InputController:_findTarget` requires all of:
  - `Available == true`;
  - 3D distance ≤ `Config.Grass.TargetDistance` (9), from `RestCFrame` if set;
  - the node inside `GrazeConeDegrees` (default 100) of LookVector, unless horizontal distance ≤ `CloseFallbackDistance` (3.5).

The Remote status card also hides the cause: it shows a total "Rejected" count with only cooldown broken out. The debug `send` line carries no geometry, so rejects can't be diagnosed from logs.
