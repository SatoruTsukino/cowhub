# Plan 4.1: CowHub memory diet

## Objective
Cut CowHub's own share of client memory. FINDINGS.md measured a clean client at 3.2–3.8 GB and a
cowhub session at 4.6–4.75 GB (about +1.2 GB, LuaHeap 656–710 MB vs 411–556 MB clean). The target is
to bring a cowhub session back to within ~200 MB of a clean client. CowHub cannot push memory below the
game's own baseline (~3.5 GB in the field). No change to feature behaviour.

## Context
- .gsd/milestones/perf-audit/FINDINGS.md (sessions 2, 3, 7, 8)
- luascripts/preview.lua (edit here first), promoted to luascripts/cowhub.lua via scripts/promote-preview.py
- luascripts/perf_monitor.lua, luascripts/perf_heap.lua (measurement)

## Suspects (static survey, line numbers from cowhub.lua @ 3bd46d1)

| # | Where | What | Why it costs memory |
|---|-------|------|---------------------|
| S1 | L901 `mapOptimizer.preloadAssets`, boot call L14892 | `ContentProvider:PreloadAsync({PlayerGui, ReplicatedStorage.CowGame})` runs on **every load**, even with Map Optimizer off | Forces every texture, mesh and sound under CowGame (all cosmetics, all menus) into memory. Best match for the +1.2 GB gap. |
| S2 | L635 `cosmetics.getProfile`, L2313 `chomp.findInput` | `getgc(true)` every 5 s until the target table is found | Each call builds an array of every GC object (millions at 500+ MB heap). Raises LuaHeap peaks and GC pressure. If the target never shows up, it repeats forever. |
| S3 | L4434 chest ESP, L871 map optimizer | `workspace:GetDescendants()` (~140k entries) | Big temporary arrays. Chest ESP also listens to every `workspace.DescendantAdded`. |
| S4 | L4932 | `collectgarbage("step", 500)` | Not supported by Roblox Luau (only `"count"`). Does nothing. Remove. |
