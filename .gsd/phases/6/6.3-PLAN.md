# Plan 6.3: Raft stuck-at-boarding fix + raft log findings

## Objective
Stop the rafting autopilot from hanging forever at "Boarding raft deck..." (server muster session left open),
and fix the issues the last 40 raft logs (38 voyages) show.

## Evidence
- 2026-11-18 stuck run: `Start` opened a muster session (RaftingSnapshot Status=Boarding, MusterEndsAt) but boarding
  needs the launch ProximityPrompt, which never shows while Roblox is unfocused. startVoyage's 25 s departure loop
  then just exits; nothing cancels. Player kept `CowRaftingTeam`; the server pinned the cow at the yard.
  `Return` and `Leave` did nothing; `Cancel` → RaftingEnded "The raft left without you" + team cleared.
- Server site levels (TeamChestSnapshot, 17 sites × ~230 samples): zone 1 = Lv1, zone 2 = Lv2, zone 3 = Lv3,
  zone 4 = Lv4. The Rafting tab dropdown labels are one level off (say zone 1 "Lv1 & 2", zone 2 "Lv3", zone 3 "Lv4").
  Plan 6.2's Sly Moon set was built from those labels: it wrongly counts Cave_Cubby01 / Clearing_02 (Lv1) and skips
  zone 4. Log proof: DailyStatus Ready with SiteId=Clearing_09 (zone 4).
- Notices: "Join a raft first." ×10, "Board the raft before setting sail." ×8, "Wait a moment." ×13 — the 5 s
  Sail/Vote fallback in startVoyage fires before the cow is aboard.
- RaftSteeringStalled ×11, the long ones (10–30 s) are all logged at Docked→Travelling right after a loot run:
  the quiet timer counts docked time. Telemetry false positive, not a steering hang.
- Healthy: 565/565 chests Opened, 0 loot errors, loot median 19 s (p90 23 s), voyage median 457 s, ~116 chests/hr.
