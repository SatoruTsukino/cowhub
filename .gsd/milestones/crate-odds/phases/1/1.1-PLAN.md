# Plan 1.1: Crate Odds Calculator (engine, GUI, presets)

## Objective
Deliver `scripts/crate_odds.py`, a dependency-free tkinter tool. Given a crate's per-rarity skin counts and
weights and the counts the player owns, it shows each tier's roll chance and its chance of an unowned skin.
The math matches `LuckRules.Weights` + `CollectionLuckRules.Weights` exactly as `CaravanRules.SkinWeights`
calls them. A dropdown loads the Halloween and Caravan crate layouts.

<task type="auto">
  <name>Probability engine mirroring the source modules</name>
  <files>scripts/crate_odds.py</files>
  <action>
    Pure function `calc(counts, owned, weights, luck, event, k_sr, k_r) -> (f, complete, per-tier results)`.

    Steps:
    1. Expand the input into skins. Drop tiers whose weight is ≤ 0, as Progress does.
    2. `luck_tier_weights`: port LuckRules.Weights at tier level: caps, the conditional OrdinaryFloor, sequential
       Mythic→SR→Rare funding, and the shortfall falling through to lower boosted tiers.
    3. Collection pity: per-skin multiplier (normal and Completed tables). Demand = base weight × (m−1). Donors are
       owned skins with demand 0, sorted by completion desc, then rank asc. Each donor gives up at most 90% of its
       luck weight. Unowned skins receive `demand × moved/need`.
    4. Normalize, then return tier %, unowned-in-tier %, and % per unowned skin.

    AVOID: multiplying raw weights for the Completed bonus, or using luck-adjusted weights for demand,
    because the source does neither (MILESTONE corrections 1–2).
    USE: tier-level luck scaling, because LuckRules scales every skin in a tier by the same ratio `var2/tbl7`.
  </action>
  <verify>
    python3 -I -c "import sys; sys.path.insert(0,'scripts'); import crate_odds as c; ..."  (run the presets through
    four cases each: none owned / all but Mythic / complete / luck 100 + event 2)
  </verify>
  <done>

    Caravan: none owned → R 98.47 / SR 1.50 / M 0.03. All but Mythic owned → M 3.00.
